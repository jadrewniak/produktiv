On 2026-11-10 the 0.1.0 tarball was installed in two new projects, one for Claude Code and one for Codex. In each project, `/pk-setup` ran, then `/pk-implement` made one small change. Both hosts set up the project, took the fast path and passed the quality gate with a receipt.

## Project

A Git repository with one commit, holding three files:

- `greet.mjs`, where `greet(name)` returns `Hello ${name}`;
- `greet.test.mjs`, which asserts `greet('Ada') === 'Hello Ada'`;
- `package.json`, with `"packageManager": "npm@10.9.0"` and `"test": "node --test"`.

## Steps

Each host ran two turns in one session, without a person in the loop:

1. `/pk-setup`. The prompt gave the onboarding answers up front: engineer, concise, Git workflow `none`, artifacts as local Markdown under `docs/`.
2. `/pk-implement greet() in greet.mjs returns "Hello <name>". Make it return "Hi <name>" and update greet.test.mjs to match.`

Each final reply stated the path, the gate result, that no review ran and that the changes were left uncommitted. In Claude Code, the first edit, made with `sed`, failed on macOS. The agent said so and redid the edit with its edit tool.

An earlier run on the same tarball used a `package.json` without `packageManager`. In that run, `/pk-setup` recorded no test command, because it does not guess the package manager. The gate then reported `UNAVAILABLE (no-commands)`, and both agents ran the test themselves and reported the gap. That run is why the project above sets `packageManager`.
