# Retry a failed job from its row

## Problem

A job list shows each job and its status. When a job fails, the person needs a way to try it again. How that recovery should look is not decided.

## Desired outcome

A failed job can be tried again from the list, if that recovery is understandable when someone uses it.

## Out of scope

Automatic retry, a retry limit, and a separate failure screen.

## Open material questions

- After a job fails, is an in-row Retry control enough for the person to see the failure and return that job to pending?
