# Execution frontier and recovery

Load for a multi-result boundary, producer/consumer dependencies, resume, or unresolved completion findings. A small independent change uses the method in implement and need not load this procedure. Verification strength belongs to `policies/verification.md`; Git delivery to `policies/git.md`; decisions to `policies/decisions.md`.

## Select and reconstruct

Explicit whole Plan means all its units and integration. A grouped Ticket means all its assigned results; a partial-unit Ticket owns only its named established boundary. An ordinary step is not a new execution target. Preserve stable IDs, scope and accepted design references.

When resuming an explicitly selected handoff, first apply `references/handoff-resume.md`; it does not reset the selected boundary or completion-assessment budget.

On resume reread current artifacts and the affected code/diff. Reconcile by responsibility, never by newest timestamp. Rebuild progress from actual implementation and fresh or still-current evidence; previous badges, checkboxes and reports cannot resurrect removed scope or prove changed code.

## Session checklist and frontier

Before multi-stage edits present stable IDs, real producer dependencies and one work state: `pending`, `in_progress`, `passed`, `deferred`, or `blocked`. Update on material state/frontier changes. This is session presentation, not `STATUS.md`, a progress file or required host integration. Verification outcomes and review severities are separate. A fixable review BLOCKER remains `in_progress`.

Check external dependencies before work. Confirm an internal producer's actual output and required evidence before editing its consumer. A unit number or “independent” label is not readiness. Earlier consumption is allowed only through a separately named, independently verifiable Plan boundary whose proof already exists. A missing producer assigned to this execution boundary is work to do, not an external blocker.

Pick ready results until closure. A blocked result does not stop independent safe work. Record each block's cause, alternatives checked and exact resume condition. A deferral requires prior owner authorization in the Issue, impact and owner/trigger; it cannot remove output a consumer needs. The no-Issue Source brief path has no deferral. Reconcile a material route/contract change through the owning artifacts before dependent work.

## Completeness and review repair

Map every owned requirement to implementation location, actual evidence and result. A partial Ticket maps its portion; a whole Plan maps all units and their integration. `passed` requires current proof. Required UNAVAILABLE evidence leaves the result blocked, unless sufficient user-supplied evidence is provided and explicitly cited. A build or green helper suite is not a missing application guarantee.

Run one completion assessment with `agents/completion-review/v5.md` after the whole selected boundary is implemented and required checks performed, not after each internal unit. A reviewer receives the selected scope, current source/contract/design excerpts, covered Plan units, relevant code/diff, quality context and command/runtime results, plus `references/review-presentation.md` and communication preferences. Do not supply executor reasoning, previous verdicts or a desired answer. Prefer a fresh context when available and authorized; otherwise apply the same rubric and disclose weaker independence. The reviewer does not edit.

Treat findings as hypotheses:
1. Validate against code and authority. Reject a false positive with evidence.
2. Fix confirmed in-scope defects, prioritizing BLOCKER/IMPORTANT; keep work in progress until material findings are closed.
3. Run the targeted checks and inspect the fix and its impact on earlier passed results. Repair concrete failures found by those checks without commissioning another reviewer.
4. Report each material finding's disposition and closing evidence. MINOR/NOTE do not block or justify optional polishing; a tradeoff is retained only if authority accepts it.

Do not expand scope to satisfy an unsupported suggestion. Fix verification is tests and focused source inspection, not another completion assessment or a renamed substitute review. On resume retain the prior assessment and reconcile remaining findings against current code; resuming or repairing the same boundary does not reset the one-pass budget. If prior review evidence cannot be recovered, disclose the gap and ask before repeating it. A separately requested new execution boundary gets its own assessment; do not split the current boundary merely to obtain more reviews. Another review of the same boundary requires a new explicit user request. Required plan review for a material route change remains separate and is not permission to repeat completion review. Unresolved material defects or unavailable required proof still prevent success; investigate concrete failures or request the missing owner decision, not a clean reviewer verdict.

## Stop and delivery

The one-pass limit caps review invocations, not repair attempts. Keep resolving every confirmed in-scope BLOCKER/IMPORTANT and checking the fixes until closed; discovering one is not permission to stop with a report or defer it to closeout. Only concrete external/authority blocks can prevent closure after independent safe work is exhausted. After whole-Plan completion, offer `/pk-closeout` as a separate whole-feature check, never as a substitute for unresolved required work.

Finish only after all owned results pass or are already authorized as deferred, integration is proved and no verified BLOCKER/IMPORTANT remains. Otherwise pause only after every remaining result is concretely blocked and independent ready work is exhausted. A host/user interruption is interruption, not completion.

Git delivery never shortens execution. An internal unit, a commit, review invocation or green suite is not whole-boundary closure. Report current checklist, evidence, unresolved causes, review independence and dirty tree or authorized commit. An incomplete selected boundary is never PASS; give its exact resume condition.
