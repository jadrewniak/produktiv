# Scoped graph evidence

Read only when the active command has an unresolved structural question that source/diff did not settle. Graph is optional corroboration of committed structure, never product/domain authority or proof of uncommitted behavior.

Check current availability (`capabilities.md`), `.workflow/config.yaml` `graph.enabled` and local `graph_opt_out`. All must permit use. Call only package `adapters/graph/index.js`, never vendor APIs. Read just the export/type needed for the selected query and scope; do not dump the graph or load adapter internals.

Queries refresh existing committed graphs as needed. Initial construction belongs only to `/pk-setup` (or an eval), through `ensure_fresh(root, scope, caller)`. Other commands must not impersonate those callers or build a missing graph. For `UNAVAILABLE` or failed stale recovery, continue from source/diff and disclose the fallback. For `PARTIAL`, treat reported coverage limitations as uncertainty. Reconcile `analyzed_sha` with HEAD; dirty files stay source/diff evidence.

Choose one scoped query for the active question, then return to the concrete files it identifies. Use `find_symbol`/`related` for a seam, `architecture_overview` for a requested structural view, or `impact_of_diff` for callers/dependents of the selected change. A result's absence does not prove there are no dependencies outside its coverage. When no query is selected, do not call the adapter or create `.workflow/graph/` or graph cache files.
