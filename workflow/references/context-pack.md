# Context pack

Use the kernel and the active skill, including its Context section. That section is a routing index, not a copy of procedures. Read only sources needed by the selected boundary; a missing optional artifact does not require creating it. Resolve resources through the installed skill's adjacent produktiv link, or workflow in this source checkout.

## Selection contract

Start with the active skill, `policies/kernel.md`, applicable repository instructions and existing communication preferences. A skill's Context section adds command-specific inputs; it does not load another skill's section. Its package paths are relative to the installed package. Required context means the relevant sections when they exist or the skill requires them, not permission to invent an optional artifact. A failed required read is unknown, not absence; stop only dependent work as the owning skill specifies.

Select by objective and canonical identity, never newest filename. Keep the selected boundary, applicable acceptance/contract constraints, producer dependencies, exact accepted visual references and evidence provenance together. Follow a pointer only until it answers a concrete missing question. Relevant dirty/untracked source must be read independently of committed graph state. Deduplicate a shared source by identity and section; pass its precise reference and necessary excerpt rather than repeating its body in every artifact. A size target never justifies dropping a governing constraint.

`May load conditionally` becomes required when its stated trigger applies. It is not a ban on necessary evidence. `Must not load by default` prevents eager loading; any expansion still needs the active skill's authority and a named unresolved question. A matched trigger does not authorize unrelated resources or edits. Keep whole-feature coverage for closeout and whole-selected-Plan execution for implement; narrow loading must not silently narrow the requested outcome.

## Graph and reviewer boundaries

Graph evidence is always conditional, never required to run a command. `references/graph-use.md` owns scoped queries, freshness, partial coverage and source/diff fallback. Commands forbidding graph use remain forbidden; no context selection initializes a missing graph on their behalf. Never pass serialized graph/cache state as a context pack.

Reviewer criteria retain their actual owners and versions in the active skills. The implement foundation preflight is an explicit plan-review consumer; execution shares implement's single completion assessment, not an additional reviewer. Load only the matching specialist, with its triggered question. Pass canonical scope/constraints, actual source/evidence and `references/review-presentation.md`, not executor narration, previous verdicts, cost preferences or rewritten criteria. The caller retains shared workflow rules; an isolated reviewer does not inherit the caller's whole session. Researcher output rules are an evidence-note contract, not a review verdict.

## Shared owners

- `references/review-presentation.md`: shared readable reviewer/caller reports, communication preferences and styling; pass to isolated reviewers, without changing their rubric or authority. Applies to plan/code/completion/simplicity/specialist review and closeout.

- `policies/decisions.md`: material choices, delegation, authorized live knowledge capture and selective ADRs. A reviewer identifies the gap but does not consent or write.
- `references/artifact-resolution.md`: identity, store/fallback, links, authority and change owners. Load for actual artifact reads/writes, not a conversation-only interview by default.
- `references/artifact-writing.md`: writes, repair, presentation and agreed splits.
- `references/visual-handoff.md`: accepted design and its handoff.
- `references/execution.md`: multi-result frontier, resume and finding repair. A small independent implementation does not load it unless that trigger arises.
- `policies/verification.md`: command provenance and required evidence strength.
- `policies/git.md`: delivery authority and preservation of prior dirty work.
- `references/design-practice.md`: practical working-interface/data-screen design when proposing missing direction or hierarchy; logic-only experiments skip it.
- `references/policy-triggers.md` and `policies/cost.md`: optional support/expensive mechanisms, not kernel baggage.
- `references/graph-use.md`: only a selected unresolved structural question; source/diff remains the fallback.

When the user or active task explicitly resumes from a handoff, read `references/handoff-resume.md` after the active skill and canonical task references. Its presence alone does not load it. No automatic per-turn handoff.

Do not read every skill's Context resources or every policy. No runtime rule engine or new host dependency is implied. All 17 entrypoints exist; remaining acceptance gates stay separate. Ship stays post-v1.
